# 图形界面（本地 Web 版）

`medshift gui` 会在本机起一个小服务，用**浏览器**完成排班。
不联网、不部署服务器、不需要安装任何前端工具链。

---

## 一、为什么是"本地网页"

| 对比项 | Tkinter / Qt 桌面程序 | 本地 Web（本项目选用） |
|---|---|---|
| 表格与拖拽交互 | 实现繁琐 | 浏览器原生擅长 |
| 界面美观度 | 受限 | 高 |
| 跨平台 | 需分别处理 | 天然一致 |
| 打包成 exe | 可以 | 可以 |
| 改动成本 | 高 | 改 HTML/JS 即可 |

代价是启动后要占用一个本地端口（仅监听 `127.0.0.1`，局域网不可见）。

---

## 二、启动

```bash
pip install -e ".[dev]"
medshift gui -c examples/radiology
```

浏览器会自动打开 `http://127.0.0.1:8765/`。

| 参数 | 说明 |
|---|---|
| `-c` / `--config` | 科室配置目录（必需） |
| `-a` / `--assignments` | 初始打开的排班 CSV；留空取 `assignments/` 下最后一个 |
| `--port` | 起始端口，默认 8765；被占用自动顺延 |
| `--no-browser` | 不自动打开浏览器 |

也可以用 Python 直接调用：

```python
from medshift.gui import serve
serve("examples/radiology", port=8765)
```

## 三、界面说明

```
┌──────────────────────────────────────────────────────────────┐
│ medshift 排班器  示例医院放射科  [周文件▾] [一键排一周][重新校验][保存][导出 Excel] │
├──────────────────────────────────────────────────────────────┤
│ ● 校验通过：未发现任何问题。                                    │
├───────────────────────────────────────────┬──────────────────┤
│            周一   周二   周三 … 周日        │ [校验][统计][班次表]│
│ 诊断组（9 人）                             │                  │
│ 医师1      CT诊断 CT诊断  休  …            │  错误/提醒列表     │
│ 医师2      休     DUTY…  值出 …            │                  │
│ 技术组（13 人）                            │                  │
│ 技师1      CT1扫描 …                       │                  │
└───────────────────────────────────────────┴──────────────────┘
```

**操作**

- **一键排一周** → 顶栏按钮，自动求解整周排班（详见下一节）。
- **点格子** → 弹出班次选择器（按「出勤／值班／值出／休息…」分组），选中即写入；
  选择器里也有「清空此格」。
- **新增班次** → 选择器底部左侧的「**+ 新增班次**」（详见下下节）。
- **新增人员** → 排班表每个班组标题行右侧的「**+ 新增人员**」。
- **删除人员** → 鼠标悬停到人员姓名上，行尾出现红色「×」。
- **改动后自动校验**（约 0.4 秒防抖），出错的格子描红、提醒级描黄，鼠标悬停看原因。
- **快捷键**：`Ctrl+S` 保存、`Esc` 关闭弹窗（求解面板最先关、其次人员表单、再其次班次表单退回列表）。
- 右侧三个页签：**校验**（违规清单）、**统计**（出勤/休息/夜班/值出/加权分）、**班次表**。
- 顶栏 **周文件** 可切换同一配置目录下的其它 CSV。
- **导出 Excel** 会按现有格式生成周表并自动下载。

**表头配色**：周末与法定节假日列底色变灰、节日名标红；调休上班日按工作日处理。

## 三之一、一键排一周（自动求解）

不想一格一格手工排，直接让求解器排好整周，再局部微调。

**触发方式**：顶栏「**一键排一周**」按钮（绿色）。

**面板字段**

| 字段 | 说明 |
| --- | --- |
| 起始日期 | 默认取当前排班表的第一天；可改成任意日期 |
| 排几天 | 默认 7 天，可设 1—31 天 |
| 保留改动 | **勾选后**，界面上当前所有格子会被锁定，求解时保持不动；不勾则整周重排 |

点「**开始求解**」，面板显示进度指示，通常几秒内完成。

**求解器会做的事**

- 护士每天保证**一个登记**、**一个正班**；
- DR 投照每天 **2 名技师**、CT2 每天 **2 名技师**；
- 诊断组人力富余时补排 **MR 审 / DR 审**（可选岗位，人力不够就留空）；
- 每人**尽量休两天**，人手不够时**至少休一天**；
- 值班次日自动配**值出**，夜班在符合条件的人之间均衡分配。

**结果处理**

- **成功**：整周排班替换到表格里，状态栏变「有未保存的改动」，右下角弹出摘要
  （排了几天、每人休息天数范围、可选岗位排了几天）。**记得点「保存」** 落盘。
- **无解**：面板里显示原因（通常是某组人数少于每日岗位需求），**不动现有排班**。
  可以先「+ 新增人员」补人，再重新求解。

> 求解器是**通用**的：它按 `positions.yaml` 里每个岗位的 `daily_need` 求解，
> 不硬编码人数。所以要改「每天几个技师、要不要审片岗」，改配置即可，不用改代码。

## 三之二、在弹窗里新增班次

排班时经常发现某个班次配置里还没有（比如临时要开「核医学扫描」）。
不必关掉界面去改 `shifts.yaml`，直接在弹窗里加即可。

**触发方式**：点任意格子打开班次选择器 → 点底部左侧的「**+ 新增班次**」。
表单展开后，原来的班次列表和底部按钮会收起。

**输入字段**

| 字段 | 必填 | 说明 |
|---|---|---|
| **名称** | 是 | 中文名，最长 20 字；不得与已有班次重名 |
| **类别** | 否 | 决定分组与是否需要夜班标记；选项来自后端 `shift_kinds` |
| **时间** | 否 | 起止 `HH:MM`；跨夜在结束时间后写 `+1`（如 `22:00` — `08:00+1`） |
| **权重** | 否 | 默认 `1.0`，用于统计里的加权分 |

**保存逻辑**

1. 前端做第一道拦截：名称为空直接提示「请填写班次名称」，不发请求。
2. `POST /api/shift` 交给后端，依次校验：名称非空/≤20 字 → 类别合法 →
   班次编码格式与唯一性（留空自动生成 `S_1`、`S_2`…）→ 名称唯一 →
   时间格式 → 权重是数字 → 颜色规范化 → 构造 `Shift` 模型。
3. 通过后**以行级追加的方式写回 `config_dir/shifts.yaml`**——刻意不用
   `yaml.dump` 整体重写，以免丢掉文件里的注释与排版；新增的 `Shift` 同时并入
   当前会话的内存配置。
4. 弹窗自动关闭，**新班次直接填入触发新增的那个格子**，并弹出一条提示。
   想把它填到别的格子，再点开选择器即可，新班次已在列表里。

**为什么写配置文件而不是排班 CSV**：班次是**配置层**的概念
（`shifts.yaml` 定义有哪些班次），排班 CSV 只存「谁在哪天上了哪个班」。
新增一个班次等于扩充字典，因此必须落盘到 YAML，否则下次启动就找不到了。

**出错时**：弹窗内红字显示后端返回的原因（如「已存在同名班次：核医学扫描」），
表单保持打开以便修正。

## 三之三、新增 / 删除人员

人员是**配置层**数据（`staff.yaml`），界面里增删会直接写回该文件，
之后所有周表立即可用。

**触发方式**

- **新增**：排班表每个班组标题行（「诊断组（11 人）」）右侧的「**+ 新增人员**」，
  表单会预选该组别。
- **删除**：鼠标悬停到人员姓名上，行尾出现红色「**×**」，点击后弹确认框。

**新增人员的输入字段**

| 字段 | 必填 | 说明 |
|---|---|---|
| **姓名** | 是 | 最长 20 字；不得与已有人员重名 |
| 组别 | 否 | 诊断 / 技术 / 护理 / 其他 |
| 编号 | 否 | 留空自动生成：诊断 `D01…`、技术 `T01…`、护理 `N01…`（取该组未占用号） |
| 职称 | 否 | 如「主治医师 / 主管技师」 |
| 在岗状态 | 否 | 在岗 / 派驻他科 / 长期假 / 外出规培；非「在岗」不参与排班 |
| 技能 | 否 | 勾选框，选项来自 `positions.yaml` 各岗位所需技能的并集 |
| 带教老师 | 否 | 选了即为进修／实习人员：随带教同格显示、不单独占岗 |
| 备注 | 否 | 自由文本 |
| 参与夜班轮值 | 否 | 勾选后进入夜班候选池 |

**保存逻辑**：前端先拦空名 → `POST /api/staff` 依次校验（组别、编号格式与唯一性、
姓名唯一、状态、带教老师存在性）→ **行级追加写回 `staff.yaml`**（保留注释与排版）→
表格立即多出一行。

**删除的联动清理**（这是最容易踩坑的部分，全部自动处理）：

1. 从 `staff.yaml` 行级删除该条目；
2. 若该人员是**带教老师**，挂在其名下的进修／实习人员会自动**解除挂靠**
   （删掉其 `supervisor_id` 行），进修人员随即恢复为可独立排班的正式人员——
   不会留下悬空引用导致配置加载失败；
3. 该人员在当前周表的排班记录由前端同步清除，点「保存」后从 CSV 落盘。

**HTTP 接口**：`POST /api/staff`（新增）、`DELETE /api/staff/<id>`（删除，
返回 `released_trainees` 列出被解除挂靠的人员）。

## 四、HTTP 接口（便于二次开发）

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/` | 排班页面 |
| GET | `/api/state?file=<csv>` | 一次性返回配置、排班、校验、统计 |
| POST | `/api/solve` | **一键自动排班（CP-SAT），返回整周结果** |
| POST | `/api/check` | 校验前端当前的排班，返回违规清单 |
| POST | `/api/save` | 把排班写回 CSV |
| POST | `/api/export` | 导出 Excel，返回下载地址 |
| GET | `/api/download/<name>` | 下载导出的 Excel |
| POST | `/api/shift` | **新增一个班次并写回 `shifts.yaml`** |
| POST | `/api/staff` | **新增一名人员并写回 `staff.yaml`** |
| DELETE | `/api/staff/<id>` | **删除一名人员，自动解除其名下进修人员的挂靠** |

`POST /api/solve` 的请求体：

```json
{
  "week_start": "2026-11-02",
  "days_count": 7,
  "time_limit_s": 30,
  "fixed": [
    {"staff_id": "D01", "date": "2026-11-04", "shift_code": "OFF"}
  ]
}
```

- `week_start` 留空时按 `days` 数组首项、再退到本周周一；
- `fixed` 为可选，列出需要锁定的格子（对应界面的「保留改动」）。

响应形如：

```json
{
  "ok": true,
  "status": "OPTIMAL",
  "objective": 1101460.0,
  "week_start": "2026-11-02",
  "days": 7,
  "off_by_staff": {"D01": 1, "D02": 2},
  "stats": {"days": 7, "people": 24, "off_min": 1, "off_max": 2,
            "optional_filled": {"MR审": 2, "DR审": 1}},
  "warnings": [],
  "assignments": [
    {"staff_id": "D01", "date": "2026-11-02", "shift_code": "DR_DIAG",
     "position_id": "DR_DIAG", "tags": []}
  ]
}
```

**无解时** HTTP 仍是 200，但 `ok=false`、`warnings` 里说明原因（前端据此提示，不覆盖现有排班）。

`POST /api/shift` 的请求体：

```json
{
  "name": "核医学扫描",
  "kind": "day",
  "code": "",
  "start": "08:00",
  "end": "17:30",
  "weight": 1.5,
  "color": ""
}
```

`code` 留空则自动生成 `S_<n>`；`start`/`end` 可空；`color` 空则按类别取默认色。
成功返回 `{"shift": {...}, "file": "shifts.yaml"}`，失败返回 `{"error": "..."}` 与非 200 状态码。

请求体统一形如：

```json
{
  "file": "2026-W42.csv",
  "assignments": [
    {"staff_id": "D01", "date": "2026-10-12", "shift_code": "DUTY_DIAG",
     "position_id": "DUTY_DIAG", "tags": []}
  ]
}
```

出错时返回 `{"error": "..."}` 与非 200 状态码。

## 五、几处设计取舍

1. **格子只选班次，不单独选岗位**——因为配置里 `Position.id` 与 `Shift.code` 是
   一对一命名（`CT_DIAG` ↔ `CT_DIAG`），界面自动按班次带出对应岗位，少一步操作。
2. **校验放在后端**——复用 `Validator`，界面与命令行结论必然一致，不存在两套规则。
3. **不引入前端框架**——没有 npm / 构建步骤，`templates/` 与 `static/` 里就是纯
   HTML/CSS/JS，改起来直接生效，也便于离线运行。
4. **只监听 127.0.0.1**——排班数据属科室内网资料，不应暴露给局域网其它机器。

## 六、打包为 exe

图形界面同样可以打包成单文件程序，目标电脑无需安装 Python：

```bash
pyinstaller packaging/medshift.spec --noconfirm --clean
```
